# Changelog

## 1.7.0 - 2026-10-27

- New `help` skill (`/dimi:help [task]`): the full catalogue, including the manual-only skills. Skills marked `disable-model-invocation: true` are left out of the model's skill list, so Claude could not see 12 of the 23 skills and told users, for example, that dimi had no skill for working through a colleague's review (`address-review`). `help` is model-invocable and loads when a user asks how to use dimi or whether it has a skill for something; it tells Claude to name the command rather than improvise the workflow.
- Session banner: the loop line says most of those commands are manual-only and points to `/dimi:help`.
- `address-review`: when `CLAUDE.md` or the author says not to commit without asking, fixes stay uncommitted with a drafted message per root cause, and replies say `Fixed (uncommitted)`.

## 1.6.0 - 2026-10-27

- Hooks no longer need `jq`. They read their input and `package.json` through `json_get` in `scripts/lib.sh`, which uses `jq` (1.6+), then `python3`, then `node`. Before this, a machine without `jq` silently lost the format-on-edit hook, the Bash guard, the Stop gate and the session-end note. They now run wherever Claude Code does: the native installer needs no Node, but almost every development machine has `python3` or `node`. The banner warns only when none of the three is present. Behaviour change for those machines: after upgrading, `eslint --fix` runs on each edited TS/JS file in repos that have eslint. Set `eslint_fix_on_edit` to `0` to keep the old behaviour.

## 1.5.0 - 2026-10-26

Fixes from a second run of every hook, skill and agent against scratch repos with the plugin loaded headlessly.

- Agent worktrees: the `implementer` agent's worktrees live under `.claude/worktrees/` until removed, and leaked into the review diff, the Stop gate's changed files, the tree fingerprint and the session banner. Those paths are now skipped everywhere `.claude/.cache/` is (`LOCAL_STATE_RE` in `scripts/lib.sh`); `review.sh gates` lists leftover agent worktrees with the removal command; the agent returns its worktree path and the cleanup line; the per-repo starter adds `.claude/worktrees/` to `.gitignore`.
- PostToolUse formatter: `ruff check --fix` no longer removes unused imports (`--unfixable F401`), so an import added in one edit survives until the edit that uses it. Prettier is detected from a config in the edited file's folder or any parent up to the project (a monorepo package with its own config was skipped).
- Stop gate: Python lint blocks only on findings at lines the change added (read from `path:line:col` or ruff's `--> path:line:col`); findings that predate the change in a touched file are reported once as a warning. Output that names no file falls back to blocking as before. Debug-leftover lines are listed once when two patterns match.
- Bash guard: a `git checkout <branch>` / `git switch <branch>` earlier in the same command sets the branch the later checks use, so `git checkout main && git push` is blocked.
- `review.sh build` falls back to the local default branch when the repository has no `origin` (the review skills and the `reviewer`/`verifier` agents stopped).
- `client-profile`: the plugin-repository check matches the remote's last path component (`…/dimi-skills(.git)`), not any URL containing the text.
- `refresh-harness`: names its commit message and says how the ticket-key guard is turned off for this repository; it stops and asks instead of committing around the guard.
- Agents: `debugger` proves the revert with a patch of its own hunks instead of stashing whole files (which took the author's uncommitted work in the same file); `verifier` drives UI checks through the repo's Playwright from Bash (it has no browser tool) and removes run artefacts; `spec-writer` removes run artefacts; `reviewer` lists `review.sh` among its allowed commands; `debugger`'s description is valid YAML.

## 1.4.0 - 2026-10-25

Fixes from an audit that ran every hook against scratch repos and invoked every skill headlessly with the plugin loaded.

- Skills that aborted on load: `commit-push-pr`, `poc`, `port`, `client-profile`, `refresh-harness`, `harden-mcp` and `review-agent` never reached the model. Claude Code's injection check rejects compound `!` commands (`case`, `{ …; }`, quoted braces), and a rejected injection aborts the whole skill; `harden-mcp` and `review-agent` failed even in auto mode. Each now pre-computes its state with one plain call to a script in `scripts/state/` (`harden-mcp` and `review-agent` share one, as do `poc` and `port`), pre-approved through `Bash(bash ${CLAUDE_PLUGIN_ROOT}/scripts/*)`. Unconfigured options arrive as the literal `${user_config.KEY}` and are treated as unset.
- Review skills (`pr-self-review`, its two checklist stages, `tidy`, `ui-states-review`, `address-review`, `compound`), the `reviewer` and `verifier` agents, and `port`: the Bash tool starts a fresh shell per call, so variables set in an earlier block were lost (a configured `default_branch` fell back to origin/HEAD; the `LATEST` pointer was never written; `port` created its worktree at `/integration`). The mechanical review steps are now one plain command each in `scripts/review.sh` (`build`, `gates`, `notes`, `record`, `worklist`, `latest`), pre-approved through `allowed-tools`: `build` saves the base, mode and options in `<Out>/context.env` and prints them, and every later step takes only that `<Out>`, so the steps cannot drift apart (a command that expands a variable cannot be pre-approved, so default mode used to ask once per block). The diff-build code has one home instead of a copy per reference section. `port`'s blocks re-derive their paths, and its cleanup finds the integration worktree it created by a marker file (never a worktree of yours).
- Stop gate:
  - works from a monorepo subfolder (it checked only untracked files there);
  - flags debug leftovers only in lines the branch added (a pre-existing `debugger` or `breakpoint()` in a touched file blocked every turn) and no longer matches `model.fit(` as `fit(`;
  - falls back to the local default branch when `origin/<default>` is missing (committed work was invisible);
  - remembers a Python-lint timeout once per branch like a typecheck timeout (it blocked every turn);
  - caps all checks at 270 s so they finish inside the hook's 300 s timeout (a larger budget meant the hook was cancelled and re-run in full every turn; override with `STOP_HOOK_LIMIT_S`); a check cut short by that limit runs again after the next edit, while one that used up its own budget is skipped for the branch;
  - prints tool output verbatim (backslashes in paths were read as escapes);
  - reads `packageManager` from the nearest `package.json`;
  - passes at most ~30,000 characters of file names to a `{files}` command (a large change ran into the argument limit; it lints `.` instead), runs commands without `{files}` from the project directory, and ignores a user `color.diff=always` or `diff.noprefix` setting when reading the diff.
- Review gates read the reviewed diff (`review.sh gates`): in PR mode the demo-marker, secrets and force-added-ignored-file checks looked at the local working tree instead of the PR, so a marker or a secret inside the PR was missed; hits now cite `path:line` of the file (not a line of the diff file) and untracked files are no longer reported twice. The added-file list comes from git, so binary and empty force-added files are caught too; a file kept by a `!` negation rule (`!.env.example`) is not reported. The local diff includes untracked files except secret and state files (`.env*`, keys, `*.tfstate`, …), whose content is never written to the diff; their names are listed by the gate instead.
- Secret scan: one regex for every gate (adds `sk_live_`/`sk_test_`, `npm_`, `Bearer` tokens, credentials inside URLs, quoted keys and values); hits keep the key name (`api_key = <redacted>`), a line without a key is masked whole, and the count past 20 is shown.
- `py_lint_cmd` default is now `ruff check --force-exclude {files}` (`--force-exclude` keeps ruff's own excludes when files are named): `{files}` becomes the changed Python files, so lint errors elsewhere in the repo no longer block. A configured command without `{files}` runs as before.
- Bash guard: `ticket_regex` accepts `\d` (read as `[0-9]`; `PROJ-\d+` blocked every commit), `protected_branches` accepts globs (`release/*`), `GUARD_DEFAULT_BRANCH` env fallback.
- Scripts share one helper library (`scripts/lib.sh`): option defaults, the secret regex and redaction, the diff parser, the timeout wrapper and the project key the hooks use for their state files (three hooks each carried their own copy, which had to stay identical for the session note to be found).
- `commit-push-pr`: the self-review report is matched on a fingerprint of the content of every changed path (`Tree:`), so committing the reviewed work keeps it current and any later edit marks it changed (HEAD alone missed edits and flagged plain commits); report file names encode the branch one-to-one (`feat/a-b` and `feat-a/b` shared one); working notes in added comments are pre-computed with the same check `tidy` uses (it pointed at tidy's greps, which it could not run).
- Secret scan: credentials inside URLs (`https://user:pass@host`) are caught and masked. Force-added-file check on a PR without a local head: GitHub's added-file list (empty files included), the diff's headers only as a last resort.
- Bash guard: `git -C /absolute/path …` is checked as if run in that directory instead of refused (the `implementer` agent's commits in its own worktree were blocked); relative or hidden `-C` paths, `--git-dir` and `--work-tree` still block. A heredoc body (`git commit -F - <<EOF … git push origin main … EOF`) is no longer read as commands; anything that only looks like a heredoc (`<<<`, `1<<n`, an unterminated body) is still checked in full.
- `port`: the pre-clean that force-removed whatever worktree sat at the integration path is gone (cleanup removes only the marked worktree); the ledger leaves the production branch with one `git rm --ignore-unmatch`; a stacked PR is retargeted by merging the default branch (a rebase would need a force push); rewrites happen in the production worktree (the integration worktree is read-only and removed at the end).
- Contradictions aligned: repo policy values live in the repo's `CLAUDE.md`/`AGENTS.md`, never in the plugin's copy; one severity mapping into `pr-self-review`; one eval-set size ladder (3–5 on day one, 10–20 for the first gate, 50–200 by pilot); `agent-evals` reports pass^k; the judge is from a different model family; the idempotency key in `review-agent` pattern 1 comes from run, step and tool-call ids; `drifted` is recorded with `poc ledger`; `address-review` names its worklist for the PR in PR mode; the guide matches the skills (address-review fetches PR comments, protected-branch globs, commit-push-pr's checks, the script inventory); refresh cadence monthly.
- Portability: `.gitattributes` pins `*.sh` to LF (a Git for Windows checkout with `core.autocrlf=true` turned every script into CRLF, and bash failed on line 1 of each); the Stop gate and Bash guard use POSIX regexes only (`\b`, `\s` are GNU grep extensions stock macOS grep may not honour). Tested on a PATH without GNU `timeout`/`sha1sum`; not yet on a real Mac or Windows machine.
- Bash guard: a push inside `( … )`, `$( … )` or backticks (`(git push origin main)`) was not checked, because the closing `)` became part of the branch name.
- Format hook: eslintrc-mode ESLint 8 rejected `--no-warn-ignored` and never fixed anything; the hook retries without it.
- Session hooks: work from a subfolder with the same project key as the Stop gate; a repo with no commits no longer writes a broken two-line note.
- `debug`: removing a probe with `git stash push -- <file>` then `git stash drop` deleted the author's own edits in that file; probes are now removed by deleting their `DBG-` lines. The bisect recipe copies an out-of-tree repro in at each step and skips untestable commits (a test committed at HEAD blamed the wrong commit).
- `commit-push-pr`: refuses to commit on the default or a protected branch; behind/ahead counts were labelled the wrong way round; the self-review gate checks the report is for this branch and HEAD and treats "Request changes" as not ready (it now matches on the tree, see above); updating an existing PR body asks first and keeps others' sections; secret hits mask bare tokens and cite file line numbers.
- `pr-self-review`: fork PRs are fetched by `pull/<n>/head` (a same-named branch on origin was reviewed instead); PR mode works without `jq`; the force-added-ignored-file check works from a subfolder; the two parallel reviewer agents each run one stage (both ran both); reports record branch, HEAD and tree; per-branch `review-worklist-<branch>.md`.
- `poc`: `init`, `mark` and `sync` check they run on the demo branch (`sync` from a feature branch merged demo shortcuts into it); `sync` commits its ledger update; new `ledger` subcommand; statuses `in-review` (PR open) and `ported` (merged). `port`: three-dot diff for a PR's own changes; points ledger updates at `poc ledger`.
- `compound` shows the report's `Branch:` line; `agent-bootstrap` landscape says "Claude Managed Agents".
- `release-notes`: Playwright `testDir` was resolved relative to the config file and found no tests; the `from..to` range argument is honoured and PRs come from the range's merge and squash subjects.
- `agent-evals`: recordings carry a fingerprint of prompts, tool schemas and model id; CI replay fails on a stale fingerprint or an unlisted skipped task, and re-recording uses the production model. One rule for real data in evals across `agent-evals`, `harness-reference` and the `review-agent` rubric.
- `agent-tool-design`, `harden-mcp`, `review-agent`: one tool-result envelope (MCP `content` carries the JSON copy of `structuredContent`, as the spec recommends; error payload `{code, message, retryable, hint?}` plus any field the hint names, e.g. `next_cursor`); new checklist row D11, and rubric B2 widened from irreversible actions to all writes, flag writes run without approval or profile permission; the idempotency key is server-derived; a service-namespace prefix is required on every MCP server (one word order per server); aligned severities, rule of two and write-approval rule. `harden-mcp` pattern 9 validates against pattern 4's `outputSchema`. `review-agent` patterns run on Python 3.9, usage normalising is None-safe, retry handles raised timeouts, and a `Retry-After` beyond the cap raises `RetryLater` to re-queue instead of retrying early.
- `agent-bootstrap`, `agent-tool-design`: `disable-model-invocation: true` (they write into the repo); trigger phrases moved into `when_to_use`. `client-profile` refuses to write into this plugin's repository and adds the profile to `.git/info/exclude` when it will not be committed. `refresh-harness` matches the as-of formats actually used.
- Docs and template: README table row with unescaped pipes; guide rule globs; starter `settings.json` has no mid-rule wildcards (`pnpm --filter * test*` matched `pnpm --filter x exec <anything> test`) and lists `git branch` read-only forms exactly (`git branch*` matched `git branch -D x`); `git fetch` is limited to `origin`, and `--upload-pack`, `--exec`, `--output` and `--ext-diff` (which turn read-only git commands into writes or command runs) are denied, as are `--force` / `--no-verify` after other arguments and nested `.env` files.

## 1.0.0 - 2026-10-24

First release of the unified `dimi` plugin (merges the former dev-workflow and fde-toolkit plugins into one).

**Development loop**
- Skills: `plan-from-ticket`, `ui-states-review`, `tidy` (remove working notes before handover), `pr-self-review` (loads `pr-correctness-scalability-review` and `pr-security-data-review` as stages; calls `review-agent`/`harden-mcp` for agent and MCP code), `commit-push-pr`, `address-review`, `compound`, `agent-tool-design`, `agent-bootstrap`.
- Agents: `explore` (haiku, read-only), `reviewer` (opus, read-only, preloads both checklists), `verifier`, `spec-writer`, `implementer` (worktree-isolated).
- Hooks: format on edit; Stop gate (debug leftovers by file class, per-package typecheck with a time budget, Python lint); Bash guard (force push, protected and default branches, `--no-verify`, sweeping `git add`, commit without ticket key); session banner on startup/resume/clear/compact. Portable across GNU coreutils and stock macOS.
- Options via `userConfig`: ticket regex, default branch, protected branches, typecheck script/fallback/budget, Python lint command and path regex, local checks line, eslint-on-edit toggle.

**Agent engineering**
- `harness-reference`: background knowledge from *The Agentic Harness: A Layer-by-Layer Guide* (facts as of 24 October 2026), split into topic files.
- `review-agent`: forked, read-only production-readiness review with a 57-check rubric, report template and tested fix patterns.
- `harden-mcp`: forked, read-only MCP server review against the 2026-07-28 spec revision (43 checks), with tested auth, SSRF and path-confinement patterns.
- `client-profile`: creates `.claude/fde-client-profile.md`, which the other skills read.
- `refresh-harness`: manual workflow to re-verify dated facts and prepare a pull request.

Every skill honours `.claude/fde-client-profile.md` when present.
